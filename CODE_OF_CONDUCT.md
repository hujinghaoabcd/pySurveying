# Code of Conduct

pySurveying aims to be a focused, professional, and welcoming open-source project.

## Expected behavior

Participants are expected to:

- discuss technical ideas respectfully;
- critique code, models, documentation, and evidence rather than people;
- make surveying conventions, units, and assumptions explicit;
- acknowledge uncertainty and limitations when a result is not fully validated;
- help keep issues and pull requests focused on the project scope;
- give credit for reference data, algorithms, examples, and prior work;
- avoid publishing private or sensitive data in issues or examples.

## Unacceptable behavior

The following are not acceptable:

- harassment, threats, or discriminatory language;
- personal attacks or sustained hostile behavior;
- deliberate misinformation about numerical validation or source provenance;
- publishing another person's private information without permission;
- spam, fake engagement, or promotional content unrelated to pySurveying;
- knowingly submitting copyrighted/proprietary datasets without permission to redistribute them.

## Technical disagreements

Disagreement about formulas, conventions, stochastic models, tolerances, or implementation choices is normal in scientific software.

When possible, resolve disagreements using:

1. a minimal reproducible example;
2. a clearly stated coordinate/unit convention;
3. an independently checkable source or derivation;
4. an automated regression test.

## Scope decisions

Maintainers may close requests that are useful in surveying generally but outside pySurveying's lightweight scope. A scope decision is not a judgment about the value of the proposed work.

## Enforcement

Maintainers may edit, hide, lock, or remove contributions that violate this code, and may restrict participation for repeated or serious violations.

If a conduct issue cannot be safely discussed in public, contact the maintainer privately through the GitHub account associated with this repository.
